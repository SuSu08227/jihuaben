# 计划本（daily-keeper）—— 手机可装的个人管理 PWA

**为什么不是微信小程序**：小程序要注册主体、开发者工具、提审发布，链路太长。
本项目是一个**可安装的网页应用（PWA）**：浏览器打开一次链接 → 「添加到主屏幕」→ 全屏运行、有独立图标，体验和小程序几乎一样，但**部署只需要一个网址**。

| 对比 | 微信小程序 | 本方案（PWA） |
|---|---|---|
| 注册账号 | 必须注册小程序主体 | 不需要 |
| 上线流程 | 开发者工具 → 上传 → 审核 → 发布 | 部署一个静态网址，10 分钟 |
| 安装 | 微信内打开 | 手机浏览器「添加到主屏幕」，全屏+图标 |
| 数据 | 本地 Storage | 本地 localStorage（同样不联网） |
| 登录 | 不需要 | 不需要 |
| 每日提醒 | 订阅消息（个人主体受限） | **系统日历**（关掉应用也能响，一次导入永久有效） |

> 功能与之前的微信小程序版完全对齐：每周计划 + 自我约束 + 预算管理 + 进度预警，数据互通（可直接导入小程序版导出的备份）。

## 1. 项目目录结构

```
daily-keeper/
├── index.html                # 单页入口：顶栏 + 视图容器 + 底部 tabbar
├── manifest.webmanifest      # PWA 清单（名称/图标/独立窗口模式）
├── sw.js                     # Service Worker：静态资源离线缓存
├── css/
│   └── app.css               # 全部样式：设计令牌 + 组件（卡片/进度条/弹层/表单）
├── js/
│   ├── core/
│   │   ├── date.js           # 日期工具：周一起始周、weekKey、月份分片、跨月枚举
│   │   ├── store.js          # 数据层：localStorage 读写、分片、导入导出、兼容小程序版
│   │   ├── calc.js           # 计算层：约束进度/三态判定/预算汇总（全应用唯一口径）
│   │   └── ics.js            # 生成 iCalendar 每日提醒事件
│   ├── ui/
│   │   └── ui.js             # UI 基础件：toast / confirm / 通用表单弹层 / 文件下载 / XSS 转义
│   ├── views/                # 五个页面，各含 render() + actions
│   │   ├── today.js          # 今日：进度、打卡、预警、预算概览
│   │   ├── plan.js           # 计划：周切换、7 天分组、增删改、复制上周
│   │   ├── constraint.js     # 约束：自定义约束项、快捷记录、撤销
│   │   ├── budget.js         # 预算：收入/固定支出/分类分配/记账
│   │   └── settings.js       # 我的：提醒设置、日历导入、数据备份/恢复/清空
│   └── app.js                # 入口：hash 路由、事件委托、提醒检查
└── assets/icons/             # PWA 图标（192/512，任意+遮罩两种用途）
```

架构要点：
- **无构建、无依赖、无框架**：原生 HTML/CSS/JS，`script` 标签直载（不用 ES Module，所以 `file://` 双击也能直接打开预览）；
- 全局命名空间 `DK.*`，加载顺序：core → ui → views → app；
- 渲染 = 每个视图的 `render()` 返回 HTML 字符串；交互 = 全局事件委托（`data-act` 属性 → `DK.actions` 注册表），一行委托代码接住全应用点击。

## 2. 页面划分方案（底部 5 个 Tab，hash 路由）

| Tab | 路由 | 职责 |
|---|---|---|
| 今日 | `#/today` | 本周完成率、今日待办打卡、**约束预警置顶条**、快捷 +1、预算概览 |
| 计划 | `#/plan` | 周切换（‹ ›）、周一~周日分组、打卡、增删改、复制上周 |
| 约束 | `#/constraint` | 新建/编辑约束（名称·类型·周期·上限·阈值·绑定分类）、快捷记录、撤销 |
| 预算 | `#/budget` | 月切换、收入与固定支出、可支配、分类预算、记一笔、消费记录 |
| 我的 | `#/settings` | 提醒时间、日历提醒导入、浏览器通知授权、阈值、导出/导入/清空 |

交互遵循移动端常见习惯：底部弹窗（sheet）做表单、居中对话框做确认/提示、toast 反馈、打卡带轻微震动（`navigator.vibrate`）、底部安全区适配。

## 3. 数据模型设计

分片原则：**计划按周、预算按月**，key 里带时间，天然避免单 key 无限膨胀。

| localStorage Key | 结构 |
|---|---|
| `dk:settings` | `{ remindEnabled, remindTime:'21:00', alertRatio:0.8, notifyEnabled, lastTipDate, inited }` |
| `dk:plans` | `{ '2026-10-26': { items: [{ id, title, note, weekday:1-7, done, doneAt, createdAt }] } }` —— key 为该周**周一**日期 |
| `dk:constraints` | `[{ id, name, type:'count'\|'money'\|'duration', unit, period:'week'\|'month', target, warnRatio, step, bindCategory, logs:[{ts, value}], createdAt }]` |
| `dk:budget:2026-10` | `{ income, fixed:[{id,name,amount}], categories:[{id,name,budget}], records:[{id,catId,amount,note,date,ts}] }` |
| `dk:flags` | 当天已提示标记，7 天自动清理 |

设计说明：

- **weekKey 用周一日期字符串，不用 ISO 周号**：跨年时 ISO 周号有边界坑（12 月末可能被算进下一年第 1 周），日期字符串加减 7 天即可切周，零歧义；
- **约束的「当前值」永远是现算的，不是存的累计值**：每次渲染按日期区间（本周/本月）重新聚合，周期自然归零，不需要任何重置逻辑；
- **约束两种计数来源**：`bindCategory` 绑定预算分类（金额类，记账自动计入）；`logs` 手动累加（奶茶 +1、加班 +1）；
- **消费记录按日期归属月份写入**：补记上月的账自动进上月的分片，汇总再按月过滤，双保险防串账；
- **兼容迁移**：`store.importAll` 会把微信小程序版导出的 `wk_*` key 自动改名导入（`wk_` → 空，`wk_budget_2026-10` → `dk:budget:2026-10` 同构）。

## 4. 本地存储方案

- **介质**：`localStorage`（同步、够快、约 5MB）。个人使用一年数据量约几十 KB，余量两个数量级；
- **读写全走 `store.js`**：JSON 序列化 + 异常兜底（超限时 toast 提示而不是静默丢数据）；
- **容量自检**：设置页实时显示占用 KB（`usageKB()` 遍历 `dk:` 前缀 key 累加）；
- **备份**：一键导出带标识的 JSON（`app:'daily-keeper'`，含导出时间），下载为文件或复制到剪贴板；恢复时校验标识再整体写回，防误导入；
- **离线**：`sw.js` 把全部静态资源缓存到 Cache Storage，装到主屏后断网也能打开（数据本来就在本地，无网络依赖）。

## 5. 定时提醒实现方式（重点）

**先说清平台限制**：浏览器出于安全/省电设计，**网页在完全关闭后无法自己定时推送**（所有网页应用都一样，不是实现问题）。所以分三层，可靠性递增：

### ① 系统日历（主推，唯一真·关掉也能响）

- 「我的 → 加入手机日历」用 `ics.js` 生成标准 iCalendar 文件：一个 `RRULE:FREQ=DAILY` 的每日重复事件，带 `VALARM` 弹窗提醒；
- 时间用**浮动本地时间**（`DTSTART:20261026T210000`，不带 Z / 不带 TZID），由日历按设备时区解释，跨时区不偏；
- 手机上点开下载的 `.ics` → 导入日历 → 保存，**之后每天到点系统日历准时提醒**，不依赖本应用是否在运行；
- 改提醒时间后重新生成导入即可（固定 UID，重复导入可覆盖）。

生成的事件核心字段（`js/core/ics.js`）：

```
BEGIN:VEVENT
UID:dk-daily-reminder@daily-keeper     ← 固定 UID，重复导入可替换
DTSTART:20261026T210000                ← 浮动本地时间
RRULE:FREQ=DAILY                       ← 每天重复
BEGIN:VALARM
TRIGGER:PT0M                           ← 到点即提醒
ACTION:DISPLAY
END:VALARM
```

### ② 应用内检查（默认开启）

- 每次打开应用、以及页面可见期间的每 60 秒，检查「已过提醒时间 && 今天还没提示过」；
- 命中则在顶栏插入醒目提醒条：今天未完成 N 项 + 已超限的约束项清单（`calc.dailyTipText` 生成文案）；
- 每天只提示一次（`lastTipDate` 防打扰），点 × 关闭。

### ③ Web Notification（补充）

- 「我的」页可申请浏览器通知权限；授权后，应用开着（哪怕切到后台标签页）到点会弹系统级通知；
- 同样受"应用完全关闭后无法自行唤醒"限制，作为 ①② 的补充而非替代。

> 如果未来想要服务端推送（Web Push + VAPID），架构上只需加一个小后端存订阅凭证 + 定时下发，前端 Notification 代码可复用。目前刻意不引入后端，保持「零账号、零上传」。

## 6. 约束阈值判定逻辑

```
current  = 本周期内已用量        （绑定分类→聚合消费记录；否则→累加 logs）
ratio    = current / target
status   = ratio ≥ 1        → danger（红：已超限）
           ratio ≥ warnRatio → warn  （橙：接近上限，默认 80%）
           否则              → safe  （绿：正常）
```

- `warnRatio` 全局默认 80%（设置页可调 70/80/90），**每个约束可单独覆盖**；
- 超限展示封顶 100%，但文案给出精确超出量（「已超出 3 杯」）；
- 预警呈现三处：今日页**置顶预警条**（红/橙底色 + 状态标签 + 剩余量，点击直达约束页）、约束卡片左边框色 + 状态徽章、记录 +1 时 toast 即时警告（超限弹「⚠ 已超限」）；
- 周期归零：`constraintCurrent` 按日期区间现算（本周 = 本周周一~周日；本月 = 当月），上周/上月的记录天然不计入，**无需任何重置任务**。

预算侧同一套三态逻辑复用在分类执行上：`已用/预算 ≥80% 橙、≥100% 红`，另有「已分配 vs 可支配」校验（分配超额红字提示）。

## 7. 部署指南

### 方式 A：直接用已发布的链接（最快）

本项目已发布为在线应用（见对话中的链接）。手机浏览器打开 → 菜单 → **添加到主屏幕** → 完成安装。

- **iOS（Safari）**：分享按钮 → 添加到主屏幕；iOS 16.4+ 的主屏 PWA 支持通知授权
- **Android（Chrome/Edge）**：菜单 → 添加到主屏幕 / 安装应用；装完桌面上就是独立图标，全屏运行

### 方式 B：自己托管（数据主权 100% 在手）

项目是纯静态文件，任何能放静态文件的免费服务都行：

- **GitHub Pages**：建仓库 → 上传 `daily-keeper/` 全部文件 → Settings → Pages 启用；
- **Cloudflare Pages / Vercel / Netlify**：拖拽目录部署，国内 Cloudflare 通常最稳。

拿到 `https://xxx` 链接后，手机浏览器打开 → 添加到主屏幕，同方式 A。

### 方式 C：本地先看看（0 成本）

双击 `index.html` 就能在电脑浏览器里打开（未用 ES Module，file:// 可直接运行；PWA 安装和日历下载需要 http(s) 环境）。或：

```bash
cd daily-keeper
python -m http.server 8777
# 浏览器打开 http://127.0.0.1:8777
```

> 注意：`file://` 下 PWA 清单与 Service Worker 不生效（仅影响"安装为应用/离线缓存"），功能与数据存取完全正常。正式使用请走 A/B。

## 8. 已通过的自测

53 项断言全部通过（Node 环境 mock localStorage/window 跑 core 层 + 5 个视图渲染冒烟），覆盖：

- 日期：跨年周（12-28 属 2026）、周日起始归前一周、闰年 2 月、跨月枚举；
- 计算：约束三态边界（80%/100%）、绑定分类聚合跨月不串账、手动 logs 周期过滤自动归零、预算可支配/待分配/消费占比、跨月补记防串账；
- ICS：RRULE/浮动时间/UTC 时间戳/VALARM/文本转义/CRLF 行尾；
- 数据：导出导入闭环、`wk_` 前缀（微信小程序版）兼容迁移、清空；
- 安全：所有用户输入经 HTML 转义，防 XSS；
- 浏览器实测：页面真实加载渲染成功（标题/路由正常）。

## 9. 与微信小程序版的关系

`weekly-keeper/`（同工作区）是功能相同的小程序版本。数据模型同构，**在小程序版「我的 → 导出」拿到的 JSON 可以直接在本应用「从备份文件恢复」导入**，无缝搬家。后续迭代建议以本 PWA 版为主（部署成本低得多）。
